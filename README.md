# TINY HEIST

**Freeze time. Change the route. Steal it. Escape.**

A mobile-first, top-down miniature stealth puzzle game. The thief walks on her own —
you never steer her directly. Instead you **hold the screen to stop time**, tap a
reachable tile to preview the route, and **release to send her**. Thirty hand-designed
jobs, every one of them proven beatable by an offline solver before it ships.

Built with TypeScript + Vite + Phaser 3. No backend, no login, no asset files —
every sprite, sound and light pool is generated at runtime.

---

## Play

```bash
npm install
npm run dev
```

Then open the printed URL on a phone (or use your browser's device toolbar in
portrait). Production build:

```bash
npm run build
```

## Controls

| Action | Input |
| --- | --- |
| Freeze time | Press and hold anywhere on the board |
| Choose a route | While holding, drag to a tile — the path previews live |
| Go | Release |
| Cancel a route | Freeze and tap the thief's own tile |
| Restart | The ↻ button, or press `R` |
| Back to jobs | The ‹ button, or press `Esc` |

Freezing is free and unlimited. **Standing still is free too** — the thief always
halts at the end of a committed path, so waiting costs nothing. What some later
levels limit is the number of *route changes* you may issue.

## Rules

- Collect **every** piece of loot, then reach the exit. The exit stays sealed until
  the last case is in the bag.
- Guards and cameras project **visible red cones**. Walls block sight; keycard doors
  do not (they are glass security gates).
- Being seen is not instant failure. A detection meter fills over ~0.55s, so brushing
  a cone is survivable if you get out. Let it fill and the job is blown.
- **Alarm beams** pulse on a fixed on/off rhythm. Touching a live beam is instant.
- **Noise floors** (hatched amber grating) do not change anyone's behaviour — they
  simply make you audible, so guards detect you from ~1.75× their normal range while
  you stand on one. The extended reach is drawn as a dashed arc while time is frozen.
- **Keycards** open the matching coloured doors, permanently.

### Stars

| Star | Condition |
| --- | --- |
| ★ | Escape with all the loot |
| ★ | Finish under the level's par time |
| ★ | Never be spotted — the detection meter never leaves zero |

## Why every level is guaranteed solvable

The rule the whole project is built around: **the game and the level validator run
the same code.** `src/game/core/` is pure TypeScript with no Phaser or DOM imports,
so it runs identically in the browser and in Node.

```bash
npm run validate           # prove all 30 levels, regenerate par times
npm run validate:verbose   # also print the proven route for each level
npx tsx tools/diagnose.ts 24   # why is level 24 blocked? which sensor causes it?
```

`tools/validate.ts` does four things per level:

1. **Builds a threat map.** Every guard patrol, camera sweep and beam is expanded to
   one frame per tick, then rasterised into a table of "is this point safe at this
   moment". Sampling happens on a quarter-tile lattice — and the live simulation
   snaps the thief to *that same lattice* before asking whether she is seen, so the
   offline answer and the in-game answer cannot disagree.
2. **Breadth-first searches the player's actual action space.** State is
   `(tile, keycards held, world phase)`. On every 250ms boundary the thief may hold
   position or step to an orthogonal neighbour — exactly what the UI can express.
   Because the search is breadth-first over a uniform step cost, the first solution
   found is the fastest possible run.
3. **Replays the proven route through the live `Sim` class** and asserts it wins
   without ever raising suspicion. This is the check that catches any drift between
   the solver's model and the real game.
4. **Counts the taps that route needs**, by compressing it against the game's own
   pathfinder, and fails the build if a level's route-change limit is below it.

Par times in `src/game/levels/tuning.ts` are generated from the proven optimal run
(×1.4), not guessed. The file is checked in and regenerated by `npm run validate`.

Current state: **30/30 levels proven solvable with a fully undetected route**,
optimal runs from 5.5s to 24.5s (median 9.8s).

## Determinism

There is no AI in this game and no randomness anywhere in the simulation:

- Guards follow a precomputed frame table. A guard's position and facing at tick *t*
  is a lookup, not a decision. Nobody investigates, nobody chases, nobody reacts.
- The simulation advances in fixed 60Hz ticks off its own accumulator, never off
  wall-clock time. The same taps always produce the same run.
- Even the audio noise buffer and the film grain are seeded, not random.

This is deliberate: if you were caught, it is because of where you were and when —
and the game shows you exactly that. On a bust, the run freezes with a beam drawn
from the sensor to the thief, the culprit ringed and flagged, and the result card
deliberately placed in the opposite half of the screen so it never hides the evidence.

## Project layout

```
src/
  main.ts                 Phaser bootstrap, scale + lifecycle wiring
  game/
    core/                 pure sim — no Phaser, no DOM, runs in Node
      constants.ts        tick rate, step length, detection thresholds

      level.ts            ASCII map -> LevelRuntime, patrol frame expansion
      geometry.ts         line of sight, cone tests, lcm

      pathfind.ts         the one route the thief will ever walk

      solver.ts           breadth-first proof that a level is beatable
    levels/               30 levels as ASCII maps, in six packs

    util/                 localStorage progression, haptics abstraction
tools/
  validate.ts             the quality gate
  diagnose.ts             per-level "why is this blocked" report
```

## Authoring a level

Levels are ASCII. Add one to a pack in `src/game/levels/`, then run
`npm run validate` — it will either prove it or tell you exactly what is wrong.

```
#  wall          .  floor         (space) void
S  start         E  exit          $  loot
1 2 3  keycards  A B C  matching doors
~  noise floor (grating)
```

```ts
{
  id: 4,
  name: 'NIGHT WATCH',
  brief: 'One guard, one corridor. Walk in behind him.',
  map: [
    '###########',
    '#........E#',
    // ...
  ],
  guards: [{ path: [[1, 6], [9, 6]], loop: 'pingpong', stepTicks: 30, pause: 60 }],
  maxWaypoints: 0,   // 0 = unlimited route changes
}
```

Keep patrol periods to numbers with a small least common multiple — the validator
refuses a level whose world cycle exceeds 5400 ticks, because the threat table is
sized by that cycle.

## Mobile / Capacitor

The project is Capacitor-ready: `capacitor.config.ts` points at `dist/`, Vite builds
with a relative `base` so the bundle works from `file://`, and the page is locked to
portrait with safe-area-aware viewport meta.

```bash
npm install @capacitor/cli @capacitor/core @capacitor/android --save-dev
npx cap add android
npm run cap:sync
npx cap open android
```

Haptics go through `src/game/util/haptics.ts`, which tries the Capacitor Haptics
plugin first, falls back to the Web Vibration API, and silently no-ops where neither
exists (iOS Safari). Nothing else in the codebase knows which back end is in use.

## Accessibility and platform notes

- Portrait, letterboxed from a 420×900 design space — within a percent of the aspect
  ratio modern phones use, so the bars are a few pixels rather than a band.
- Sound and haptics are independently toggleable from the title screen; both persist.
- Audio only starts after a user gesture, as iOS requires. The ambient bed suspends
  when the tab is backgrounded.
- Progression is stored in one `localStorage` key and degrades to "new save" if it is
  missing or corrupt — private browsing never throws.
